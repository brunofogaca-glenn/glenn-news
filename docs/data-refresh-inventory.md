# Glenn News: inventory and refresh policy

This inventory distinguishes editorial article ingestion from the supplemental fact panels on the homepage. Times are local to `Europe/Stockholm`; Vercel cron expressions themselves are UTC.

## Editorial article sources — do not fetch before 06:00

| Source / code | Purpose | Rule |
|---|---|---|
| `lib/rss.ts` / `FEEDS` | RSS feeds for the article pool | Never fetched before 06:00 |
| `lib/webSources.ts` / `WEB_SOURCES` | Extract editorial article links from publisher pages | Never fetched before 06:00 |
| `lib/feedHealth.ts` | Checks the health and freshness of RSS and editorial web sources | Never run before 06:00, because checks perform live requests |
| `lib/dailyEdition.ts` | Builds and persists the morning edition | Explicit guard prevents editorial fetch before 06:00 |
| `app/api/cron/refresh-articles/route.ts` | Manual recovery of the article cache and feed-health status | Manual GitHub Actions dispatch only. The automatic morning refresh is owned by `app/api/cron/refresh-news/route.ts` during the 06:00–06:59 Stockholm hour |
| `app/api/cron/refresh-news/route.ts` | Publishes the morning edition | Accepts the entire 06:00–06:59 Stockholm hour because Hobby cron start minutes are not guaranteed; a second invocation retries only when needed. Protected by production `CRON_SECRET` |

The homepage, direct feed-health page, and manual refresh action are also gated so they cannot initiate article-feed requests before 06:00. The sports-panel loader no longer imports or calls the editorial article cache.

| Source / code | Data | Existing cache lifetime | Failure handling |
|---|---|---:|---|
| `lib/sportDay.ts` + `lib/sportDayCache.ts` | Fixtures, results, league table and scorers (API-Football/FotMob; optional Sportmonks enrichment) | 1 hour | Failed refresh reuses last good snapshot when available |
| `lib/marketDay.ts` | Market indices and daily changes (Yahoo Finance) | 24 hours | Empty/failed market response is treated as a failure, not new valid data |
| `lib/dailySnapshots.ts` — local | Borås.com events and Borås Stad meetings | 2 hours | Total upstream failure throws so last good snapshot can be reused |

| `lib/dailySnapshots.ts` — world | Market indicators, central-bank rates and World Bank GDP | 3 hours | Total upstream failure throws so last good snapshot can be reused |
| `lib/dailySnapshots.ts` — culture | DN film and album review RSS feeds | 4 hours | Fetch failure throws so last good snapshot can be reused |

## Actual schedule and ordering

All times below use UTC in cron expressions and `Europe/Stockholm` in code. Vercel Hobby Cron can invoke a job at any minute within the selected UTC hour; GitHub Actions scheduled workflows can be delayed substantially or dropped under load. Do not assume a GitHub `schedule` run starts near its cron minute.

- **Supplemental homepage fact panels** use Vercel Cron, not a scheduled GitHub Actions workflow. `vercel.json` schedules `/api/cron/refresh-data` at `13 0 * * *` and `13 1 * * *` UTC. On standard time, the invocation windows are 01:00–01:59 and 02:00–02:59 Stockholm time; during daylight-saving time, they are 02:00–02:59 and 03:00–03:59. Both are safely before the 06:00 cutoff. The second entry cheaply skips if the first run succeeded on that Stockholm date, and retries incomplete/failed runs. The route accepts the production `CRON_SECRET` bearer token for Vercel Cron and repository/workflow-scoped GitHub Actions OIDC for manual recovery. Calls outside 01:00–05:59 Stockholm time return HTTP 503, never a successful skip.
- **Borås.com events** are browser-scraped with Playwright by `.github/workflows/refresh-boras-events.yml` at minute `:13` during UTC hours `00`, `01`, `02`, and `03` (four scheduled opportunities per day). These map to 01:13–04:13 CET and 02:13–05:13 CEST, safely inside the 01:00–05:59 Stockholm write window. The workflow uses a serialized concurrency group with `queue: max` so retries are not replaced by newer pending runs. Before installing Playwright, each attempt calls the authenticated read-only GET preflight on `/api/cron/ingest-boras-events`; if today's Stockholm-date snapshot contains at least six valid upcoming events, it skips browser setup, scraping, ingestion and Blob writes. Otherwise it scrapes and saves through the POST route. Successful ingestion rebuilds the merged local snapshot immediately so new events cannot remain hidden behind an older snapshot. The workflow and route fail visibly if a delayed run misses the write window.
- **Fotbollskanalen articles** are browser-scraped by `.github/workflows/refresh-fotbollskanalen-articles.yml` at minutes `:17` and `:47` during UTC hours `00`, `01`, `02`, and `03` (eight scheduled opportunities per day). This creates repeated opportunities inside the 01:00–05:59 Stockholm write window (01:17–04:47 CET; 02:17–05:47 CEST). Its serialized concurrency group now sets `queue: max`, retaining pending retry runs instead of replacing them. Each run calls the authenticated read-only GET preflight on `/api/cron/ingest-fotbollskanalen-articles`; if a snapshot has already been saved on the current Stockholm date **and** its newest article is no older than 72 hours, Playwright setup, scraping, ingestion and Blob writes are skipped. Both the scraper and ingest endpoint reject a scrape whose newest valid article is older than 72 hours, preserving the previous snapshot and making the retry fail visibly. The POST route still rejects writes outside the window, and an out-of-window scheduled run fails visibly.
- **Reader history** is consolidated by `.github/workflows/process-reader-history.yml` at `01:15 and 02:15 UTC`, giving two opportunities within the Stockholm maintenance window. These map to `02:15/03:15` in CET and `03:15/04:15` in CEST. Scheduled runs and manual recovery dispatches must start from `01:00–05:59 Europe/Stockholm`; outside-window runs fail visibly. Only a push that changes the restricted `.github/run-reader-history-migration` path may append `?manual=1` for the one-time migration override. The workflow serializes runs so ledger/snapshot writes cannot overlap. The profile snapshot records `sourceLedgerUpdatedAt`; repeat runs skip rewriting it when it already matches the ledger, while still retrying eligible Week Focus read marks and Saturday precomputation.
- **Editorial articles and the saved morning edition** are refreshed through `/api/cron/refresh-news` during the 06:00–06:59 Stockholm hour. Four Vercel Cron entries cover both UTC offsets and the second eligible invocation retries only when article status says `retry`. A valid already-published edition is skipped. The endpoint is protected by the production `CRON_SECRET` bearer token; a spoofed `User-Agent` is not accepted. `/api/cron/refresh-articles` remains manual recovery only.

GitHub Actions workflows call fixed production URLs and authenticate with short-lived OIDC tokens scoped to this repository, `main`, and the specific workflow. They use audience `https://glenn-news.vercel.app`. The repository must have `VERCEL_AUTOMATION_BYPASS_SECRET` in Actions secrets so workflows can pass Vercel SSO protection; this bypass does not replace route-level OIDC authorization.

On 27 October 2026, the supplemental GitHub scheduled workflow started at 06:37 Stockholm time although its cron expression was 00:43 UTC. Its time-window guard skipped the endpoint call, yet GitHub reported the job as successful. Moving supplemental refresh to two Vercel Cron windows, retaining GitHub Actions as manual recovery, returning HTTP 503 on missed windows, and adding regression coverage addresses this specific silent-skip failure mode. The browser-scraping workflows still depend on GitHub Actions, but a missed time window now appears as a failure instead of a green no-op.

## Snapshot persistence

`lib/supplementalCache.ts` stores the most recent successful supplemental result in private Vercel Blob storage for weather, sport, market, local, national, world, culture, and daily-header data. Returned values include refresh metadata: status, last attempt, last success, and whether the snapshot was persisted. Failed upstream calls return the last known good payload when available, rather than replacing it with empty data.

The refresh route respects source-specific intervals when deciding to force tag revalidation: weather, sport and national data 1 hour; local 2 hours; world 3 hours; culture 4 hours; market data is proactively refreshed after 20 hours; daily-header data 7 days per date key. The market module's underlying cache TTL remains 24 hours, but the refresh threshold is shorter so the nightly job still updates the market snapshot when the previous run occurred late in its allowed hour and the next one starts early. Stale sources can retry after 25 minutes. A successful report for the current Stockholm date makes the second cron invocation a cheap no-op; a failed/incomplete report remains eligible for retry.

## Operational caveats

- A successful HTTP response can still contain malformed or incomplete content. Tighten source-specific validation whenever a provider's response schema is known.
- Market values must be interpreted using their observation date, not only the snapshot fetch time. If Brent (`BZ=F`) is older than the latest date among the other market indicators, the world snapshot is marked stale, the last-good snapshot is preserved rather than overwritten with the partial result, and the second nightly refresh remains eligible to retry. The homepage shows a per-Brent observation-lag label and an overall stale-snapshot warning. A correct older close can still be normal on non-trading days; the comparison flags source lag, not a universal same-day requirement.
- The ordinary HTML fallback for Fotbollskanalen is intentionally fetched with `cache: "no-store"`: its page response exceeds Next.js's 2 MB data-cache limit. Other publisher web sources retain their 15-minute Next.js revalidation. The preferred Fotbollskanalen path is the validated, private browser-scraped Blob snapshot.
- The Sportdygn league-table provider payload consumed by `lib/sportDay.ts` does not expose a distinct observation timestamp. The UI therefore labels the time Glenn News retrieved the table, explicitly says that it is not the underlying observation time, and displays stale last-good snapshot metadata where available. Do not equate snapshot retrieval time with proof that the table itself was updated.
- No RSS or editorial article-source request is permitted before 06:00. Supplemental snapshots run through Vercel Cron before the morning edition. The 06-hour publication endpoint refreshes RSS and feed health, then saves the dated edition; the homepage can generate a fallback edition after 06:00 if scheduled publication fails.
- Vercel Hobby Cron also has start-time jitter and does not automatically retry failed invocations; the two supplemental entries reduce dependence on one invocation but do not guarantee provider availability. If both miss/fail, check the **Nattlig uppdatering** report and Vercel Runtime Logs, then use GitHub Actions manual recovery during the permitted nightly window.
- Browser-ingestion and reader-history jobs remain GitHub Actions schedules. Their queues can delay runs; a missed local-time window fails visibly instead of reporting a successful no-op. Manually dispatch a recovery only from `01:00–05:59 Europe/Stockholm`; never weaken the window guard to make a delayed run green. The reader-history workflow validates the endpoint response so an API-side skipped result is also reported as failure.

## League table markers

`lib/leagueZones.ts` only returns a zone configuration when the table season begins in 2026, matching the rules catalogued for this release. Promotion, playoff and relegation bands are based on current domestic competition rules. UEFA league-phase positions follow UEFA's 2026/27 format: ranks 1–8 qualify directly for the round of 16, 9–24 enter the knockout playoffs, and 25–36 are eliminated (https://www.uefa.com/uefachampionsleague/news/0291-1bd88ae04870-e1e038c319e3-1000--champions-league-league-phase-standings-how-teams-level-on-/). European places in domestic leagues are deliberately marked preliminary because UEFA performance places, national cup winners and the access list can change the final cut-offs; the UI explains this rather than presenting them as guaranteed.

The 2026 Swedish league playoff rules use the Swedish Football Association's current guidance (https://www.svenskfotboll.se/serier-cuper/kvalspel/kval). English Premier League provisional Europe bands are based on the league's explanation of how cup winners and UEFA performance slots alter qualification (https://www.premierleague.com/en/news/4671711/how-crystal-palace-uefa-conference-league-final-affects-european-qualification).
